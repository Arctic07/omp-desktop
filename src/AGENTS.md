# OMP Desktop — frontend rules (`src/`)

Read root `rules.md` and `AGENTS.md` first. This file states how the frontend is built: the only frontend in the repository, wiring the real engine over IPC. `src/rules.md` holds the design-system, component-library, and file-size rules. On conflict, these files win for frontend code.

## Stack and boundaries

- React 19 + Vite + TypeScript in a Tauri desktop window, wired to the real engine over IPC — not a set of static pages. No mock data, no placeholder screens, no invented numbers.
- Run `pnpm tauri:dev` (`identifier` `com.omp.desktop.dev`) and `pnpm tauri:build`. `src-tauri/tauri.conf.json` is the configuration (`devUrl` 1421, `frontendDist` `../src/dist`); `tauri.dev.conf.json` overrides only `identifier`, which is what keeps dev's data root and WebView2 profile apart from the installed application.
- IPC only through `src/api/**`. `types.ts` and `session-types.ts` are wire DTOs, field names verbatim from the Rust `#[serde(rename)]`; `client.ts` is the only `invoke`; `agent.ts` wraps commands. Components and stores never compose command or channel names.
- State only through `src/state/**`. `store.ts` wraps `useSyncExternalStore`; `useStoreSelector` returns a field or an existing reference, never a new object (an infinite re-render loop).
- Store fan-out catches per subscriber (`store.ts::set`): a throwing selector must not break the writer (`sendPromptTo` writes the reader's row, then sends) or abort a fold. Never revert to a bare `for (...) listener()`.
- No `any`, `@ts-ignore`, `@ts-expect-error`. One file at most 1000 lines; longer splits by domain.

## Startup surface

- The first frame is `index.html`'s `#omp-startup` shell: faded after `omp-startup-ready`, which `src/main.tsx` sends once the first frame has painted and the first workspace read has settled (5 s ceiling). It is never a React component.
- **The entrance paints nothing until the palette is known.** `src/main.tsx` sets `data-omp-startup-paint` on `<html>` after adopting the record and applying the plugin theme; the gate rule holds the canvas, the body, the overlay and the mark back until then, so what shows first is the surface the desktop painted from the record. A document whose application never runs is painted by the shell's own ceiling (2.5 s, longer than the theme read's), in the mode pair. The mark reads the palette's own `--background` / `--foreground` (a plugin theme's tokens included), so the entrance wears what the application is about to paint; never paint it from the shell's storage answer alone (2026-11-05: a mark in the other palette is a white bar under the loading panel on a dark window).
- **The palette class goes on `<html>` in the inline script, before any stylesheet applies.** That script resolves the stored theme to `light`/`dark`; `index.css` carries both palettes on one set of custom properties (`:root` light, `.dark` dark) and is a render-blocking `<link>` in the built document, while `next-themes` adds the class only after React's first commit. Never move that line into `main.tsx` or `next-themes`, and never give `:root` a dark `--background` to "solve" it - a light theme then flashes black instead.
- **The shell raises the window, not the bundle.** `index.html` calls `main_window_ready` through `window.__TAURI_INTERNALS__.invoke` on the second `requestAnimationFrame` after the shell markup, with a 300 ms timer as the guarantee because a hidden window may not run rAF at all. `main.tsx` keeps its call (idempotent) and Rust keeps its 1.5 s ceiling, which the module graph loses to in dev; never tie the reveal to the bundle, and never raise the window from Rust `setup`.
- The shell's colours stay identical to `src-tauri/src/services/appearance.rs`.

## Session records and the stream

Modules: `session-store.ts` (lifecycle and app wiring), `session-record.ts` (record, write primitives, folds), `session-stream.ts` (read half), `session-send.ts` (write half), `session-visits.ts`, `session-lists.ts`, `restored-prompts.ts` (input a stop withdrew).

- One listener per session (`ensureListening`, deduped by id); `stopListening` is the only release path. A second listener folds every frame twice, and the text visibly stutters and duplicates.
- Leaving a conversation keeps it warm: `releaseLater` holds the listener and the host session for `WARM_RELEASE_MS` (60 s) and narrows the streaming window to `BACKGROUND_DELTA_FLUSH_MS`; only then `letGo`. The warm set is capped by `WARM_RECORDS` (5). Re-entering a warm record opens nothing and re-reads no transcript. Never close on leave.
- `records` keeps 16 sessions by visit order plus `RETAINED_MESSAGES` (4000 rows), enforced by `pruneRecords`. Active, warm, running, and queued sessions are exempt.
- Frames batch on the app-wide beat in `state/presentation.ts`: `requestAnimationFrame` when visible and focused, a 250 ms timer otherwise; queue cap 512; one fold and one store write per session per beat. `focus`, `blur`, and `visibilitychange` call `flushPresent()` and synchronize `session_watch(active, viewing)` with `app_background(!viewing)`. A frame that changes nothing writes no store. `setConversationCovered` treats a covering page (settings) as unseen: the 250 ms cadence, `use-smooth-text` snapping, `session_watch` unwatched — never `app_background`.
- Turn end comes from `turn_finished` only. `runtime.isStreaming` stays OR-ed in `session-record.ts::isStreaming` until `foldTranscript`'s `turn_finished` clears it — otherwise the rail shows a permanent spinner, the footer never appears, and the send button stays a stop button.
- `mergeTranscript` pairs live and file rows by `kind + at + text`, because ids differ between the two paths. A row the file will never have (a host-run command such as `/compact`) keeps its own position instead of being appended. `confirmUserMessage` claims the nearest-in-time row, not the oldest unclaimed one.
- Transcript reads address `record.filePath`; `rejoin`, `letGo`, `ensureListening`, and `openConversation` guard every step with generation tokens, so a stale trip cannot open, write, or close a newer one.
- Background reclamation starts only after 15 s blurred or hidden and drops only idle warm sessions; returning to the front re-checks `session_watch(true)` and `rejoin`s when the host no longer holds the session.
- The stall watchdog (`state/session-stall.ts` with `session-activity.ts`) watches each record's frame clock: 3 minutes draws a `ConversationStall` row, 10 minutes calls `session_force_stop` and `afterReclaim`, and "keep waiting" snoozes 30 minutes. It runs only while a turn is in flight with no retry, pending dialog, background job, pending async work, or cancellable subagent. Every record removal releases the clock.
- Reader position (scroll and following) lives in `reader-place.ts` maps, not in the store.

## Turn edges

- Read marks compare `SessionReadMark.seenAt` with `updatedAt`, never status words. A turn that ends while the reader watches it (`activeId === sessionId` **and** `document.hasFocus()`) or that the reader stopped (`lastTurn.stopped`) is marked read at once in `noteTurnEdge`; window focus settles the visible conversation the same way. Never key off `activeId` alone.
- The taskbar flashes only when the ending is off screen, decided in the frontend (`noteTurnEdge` → `flash_taskbar`): never unconditionally in Rust, never for subagents, never as an overlay badge.
- Retry is drawn on the waiting row ("reconnecting n/m" with the engine error in `title`), not as a notice, and without a backoff countdown.
- One ending row per turn, only after the turn ends, only on that turn's last assistant row (or its user row). Only `aborted` and `error` are endings; `toolUse` and `length` are not. Steps retried away (`retriedAwaySteps`) draw no ending. Order: `flush()` → `settleEnding()` → `closeTurn()`.
- Engine progress codes (`engine_retrying`, `engine_compacting`, …) are not written as notices; the screen already states the same fact.
- A stop is one press at a time (`SessionRecord.stopPending`; a second press is dropped, never queued). The host withdraws the engine's queued steer or follow-up before aborting and answers with the words (`restored`): their local rows leave the transcript and return to the composer draft (`state/restored-prompts.ts`). While a stop is in flight a submission queues instead of steering — a prompt racing the abort is refused as busy and would add an error line on top of the stop.
- A queued message's head row is not steered: pressing it ends the running turn first (`state/session-send.ts::endTurn`) and sends the row as the next turn, because `steer` only joins the live run and waits for a model-call or tool-batch boundary, so the answer already streaming keeps coming. A failed ending returns the row to its queue head, and the control is disabled while a stop is in flight (`state/prompt-queue-runner.ts::interruptQueuedPrompt`).
- A sent message moves its rail row's `updatedAt` to the send (`state/session-rows.ts::rowWithSentMessage`, applied by `noteSessionWritten` and by every scan's `withHeldMessages`): the rail sorts by it, the list is re-read only at a turn's ending, and the file's `mtime` lags the send, so a row that waited for the ending stayed put for the whole answer.
- The `message_finished` frame carries the message's whole `text` and `thinking`; the fold sets the row from those, never from the sum of deltas. A row completed only by deltas read as "green end, no answer" until a reopen.

## Composer

`ConversationComposer.tsx`, `components/agents/composer-field.tsx`, `composer-editor.ts`, `state/composer-*`.

- Model and thinking level are writable with no session: `engine_set_model_role('default', …)`, thinking as that role's `:<level>` suffix (`auto` clears it). Never `return` when `activeId` is null — that pins thinking to `auto` and makes the select snap back. A session's thinking change writes only that session; app defaults are never overwritten by it, and a reopened session follows the engine's own record.
- A successful write is patched onto the row immediately; a failure surfaces as a composer notice.
- `namedModel === null` disables the thinking select **and** send, and `submit` re-guards, because Enter, form submit, and queue all pass the same guard. An empty catalogue means a read-only composer, by design.
- A model that cannot think gets no strength control: the session publishes an empty `thinkingLevels` (`host/src/session-view.ts::thinkingLevelsFor`), `lib/thinking-levels.ts::thinkingLadder` reads `[]` as "no stops" and `undefined` as "not reported yet" (full ladder), and the composer hides both the slider and the chip's `· level`. `models.yml` states `reasoning: false` explicitly — omitting the line let the engine inherit a same-id bundled model's `true` (`removed:notes/implemented/bug-fix/2026-10-29-reasoning-written-both-ways.md`).
- Enter respects `busyBehavior`, Ctrl/Cmd+Enter takes the other, Shift+Enter is a newline, and a plain prompt goes out when idle. One queued prompt is released per `turn_finished` (`promoteQueuedPrompt`); aborted and failed turns release too. The primary button follows `isStoppable`, not `isWorking`.
- The field is one `contenteditable`; one attachment is one private-use character rendered as a chip, so files sit inside the sentence. Drafts are per seat (`Record<seat, {text, attachments}>`), `new:<workspaceId>` for a blank session; only two handoffs exist (empty key → first session, blank seat → its own session). Never a controlled field.
- A sent message is the draft itself; the host appends `@<path>` mention lines and reads them back as attachments. Rendering pairs tokens with attachments by position (`composer-draft.ts::messageSegments`) — feed, queued rows, and Markdown copy alike. Plain-text surfaces (rail cards, titles) strip the tokens.
- One chip shape (`styles/file-chip.css`) serves field and bubble. An image chip click opens `AttachmentViewer.tsx` in a full window; non-image chips are not clickable.
- Undo and redo belong to the field (`composer-undo.ts`, 100 steps) because `replaceChildren` clears the native stack; a restore writes the attachment records back to the store instead of only redrawing the DOM.
- Copy carries `@<path>` plus the real file list (`copy_text_and_files`); the Web clipboard cannot write file lists. The words copied are the draft slice, never the chip's visible label (`selectionCopy` does the same for a selection over the feed), because a label pasted back is the file's name written as prose beside its own chip. Every copy surface also remembers where its chips stood (`WrittenFileCopy.placements`), so a paste of it restores those places unless the draft already holds that path (one chip per path); a clipboard from elsewhere lands its files at the caret. Cut uses that same write (`writeSelection`) and then deletes the draft range itself: one undo step, the cut chips' records pruned with their characters, and a text-only cut left to the browser.
- Arrow history walks the current session's user rows only, starts from an empty draft, and replaces the seat's draft.
- A leading `/` lists engine commands from `SessionRuntimeState.commands`; selecting injects `/<name> ` and never sends.
- Paste yields files or plain text only; HTML paste is refused. A copy this page wrote is recognized by its exact text (`lib/clipboard.ts::recallOwnCopy`) and returns as its own words plus its own paths — chips attached by path, never the mention block as prose. Any other clipboard is read on what it carries (`recoverPastedText` when the page sees files and no text): this application's copy by its mention block naming exactly those files (`carriesOwnFileMentions`) is words plus chips; a browser or document snapshot (words plus one picture) keeps only the words; anything else is the files. Never decide that on file types alone — a message copied here is also "words plus an image", which is how a copied image came back as text.
- A drop lands at the caret, never under the pointer: the release point says nothing about where the reader was writing.
- An engine dialog (`home/ConversationDialogs.tsx`) answers with its own field (`DialogAnswerField.tsx`): a textarea two rows tall that wraps and scrolls, plus pasted or dropped files as chips. Both drop surfaces register at once and the pointer decides (`state/desktop-drop.ts::targetAt`, overlay before the composer's own box); `over` and `overlayOver` keep each face dark under the other. The answer leaves as one string — the words, then one `@<path>` line per file (`lib/file-mention.ts::promptTextWithFiles`, a single newline because the transcript reads those lines directly behind the words) — which the engine reads itself. `ApprovalCardQuestion.field` is the slot, and the card keeps its submit gate so a file-only answer still submits.

## Transcript

`ConversationPane.tsx`, `AssistantRow.tsx`, `conversation-rows.ts`, `ConversationFeed.tsx`, `ConversationTurnTail.tsx`.

- One lane: composer and every row share `--omp-conversation-lane` and `px-3`. Never pad one side to make room.
- No avatars; one speaker per turn (`namesSender` / `claimName`, claimed by the first row actually drawn). Headers and inline notes carry no horizontal padding, so speaker, body, and tool icons share a left edge.
- One footer per turn, on the last drawn row, only after the turn ends; the latest is always visible, older ones on hover or focus. Usage is `input + cacheWrite + output`; `cacheRead` is listed separately and never summed. A missing bucket is not drawn.
- Thinking groups per contiguous segment and stays expanded until its own answer starts. Tool calls never auto-expand (a `task` batch does while its roster is live; a `web_search` row is its own, never in a folded group, and opens once it has a card — a source list or a provider answer — so a search still in flight stays folded). `AgentDisclosure` unmounts children when closed; closing animates `height` and `opacity` through WAAPI, duration derived from height, sine ease-in-out, `cancel()` before unmount; an interrupted fold measures and starts a new animation. Never mount-and-clip.
- Tool rows: `web_search` renders result cards on its own row, open once that card exists; `task` renders the roster (`TaskAgents.tsx`) and a roster row opens that subagent's conversation. Row status is `taskRowStatus` (a settled subagent's words beat the call's own). A collapsed group shows a one-line intent summary.
- Tool-output images are always visible: `ToolResult`'s `afterHeader` slot, and an image call never joins a folded group. Several images sit in a grid; a click opens the full-window viewer.
- A step's own reasoning markup is read once, in `buildRows` (`home/reasoning-echo.ts::readModelReasoning`): a model's `previous_reasoning` or `<thought>` envelope joins the row's thinking, and a reasoning channel that carries the answer after a `</thinking>` transition marker hands it back to the bubble — the answer, in the footer's copy, the conversation copy, the rail's card and `/btw` alike, and the markup nowhere.
- A step whose words are a tool-call envelope the engine never parsed is read the same way (`home/tool-call-markup.ts::readStrayToolCall`): the row draws the call it named as a `ToolResult` card, plus a `miscall` note. A fragment the step appended to a real answer is cut from the words instead (`stripToolCallMarkup`, composed into `stripModelTags`), so no markup reaches a bubble, copy, or preview. An attribute-form call (`<ask i="…" questions="[…]">`) ends at its closer, its `/>`, or the end of its line; the element spellings end at their closer or their paragraph and always need a complete opening tag. A call that never said where it ends is claimed only at the head of a line. Code keeps what it quotes (`home/code-ranges.ts`, one reading for every surface).
- Streaming text is revealed by backlog pacing (`lib/reveal-pacing.ts`, `use-smooth-text.ts`); the smoothed string is never written back to the store, and transcript, copy, and previews always read the full text. Follow-scroll uses its own rAF easing (`lib/follow-scroll.ts`).
- Long user messages collapse to 5 measured lines; collapsing is view-only.
- Syntax highlighting runs only in `code-highlight.worker.ts`, with a bounded LRU token cache; language tables are split (`code-language.ts` for the main thread, `code-language-loaders.ts` for the worker only); a failure or timeout degrades to plain text and disables the worker. Production CSP keeps `wasm-unsafe-eval` and `style-src 'unsafe-inline'`.
- `lib/error-boundary.tsx` wraps the conversation body, the shell, and settings; `getVirtualItemForOffset()` is always reached through `virtualItemAt()`.

## Rail, sidebar, columns

- A rail item is one turn: title is the user ask (50 chars), body is this turn's final answer (120 chars) only after the turn finished, never rewritten by deltas.
- The running glyph is the beUI spinner (`components/motion/loader.tsx`) on the single module-level clock: never a per-element `rotate`, never `LoaderCircle`. `cancelled`, `pending`, and `error` have their own marks.
- `runningSessionIds` is every conversation with a turn in flight in this process, never just `activeId` (`state/work-readings.ts::runningSessionsKey`); a session merely holding background work is not running, and `isWorking` is that wider lifetime gate.
- Status marks and their colours exist once (`components/agents/status-mark.tsx`, `ConversationStatus`); the rail row and the vibes roster both draw it.
- A newly added workspace expands itself when its session count goes 0 → 1.
- The left column's second row is conversation search over the already loaded list: title matching only, no archived rows, panel width equal to the trigger row, Up/Down/Enter/Esc with focus returned to the row.
- Blank sessions are not listed (`isListedSession`). The first message is recorded locally (`noteSessionWritten`, `withHeldMessages`) instead of waiting for the engine's file. List replies land by ticket (`list-sequence.ts`); the Rust index retries ENOENT and shows only `.bak` rows whose transcript is otherwise missing.
- One blank seat per workspace (`state/blank-seat.ts`): reuse it when clean, open a new one when it still carries modes, keep it alive while the right sidebar owns work in it. An empty session never restores plan mode.
- Hero is the column's `flex-1` body, never part of the composer stack, so the composer rect is identical in hero and conversation states. Hero exit and transcript entrance form one crossing animation: displacement `EASE_OUT`, opacity `EASE_IN_OUT`; the welcome fades out, the transcript never fades in or out — it is drawn at full weight and rises, and a conversation the reader leaves is replaced in the same frame. Verify by comparing `.omp-composer-frame`'s `getBoundingClientRect().top` across send and "new conversation".
- **No text surface is held at zero opacity by an animation.** Rows and bubbles open at full weight and only move (translate or scale); the pop-in belongs to rows arriving while the pane is up (`home/conversation-arrivals.ts` reads the ids the pane had already drawn), so switching draws a stored conversation as a still instead of animating every row, and an interrupted animation can never leave a mounted transcript blank.
- "Open in" is host-detected (`services/open_in_app`); the page never scans PATH and never draws brand icons itself. Icons are the application's own or one generic `AppWindow`. Menus are unmounted, not hidden, while the panel is expanded.
- Menus (`home/MenuBar.tsx`): File opens the same `TOOL_MENU_ENTRIES` through `openToolTab`; View runs `location.reload()` (re-attach only, never aborting a turn); Help holds About and the release feed's check; an announced release adds the title bar's update pill (`home/UpdatePill.tsx`). A blank session greys out the git and file tabs, which read the transcript, through `components/workspace/tool-menu-entries.ts::toolEntryLocked`.

## Right sidebar

- Panel state is keyed by session id (open, expanded, tabs, activeTab) in `state/panel-store.ts`, never window-level. Reconciliation may add a missing terminal tab but never changes `activeTab`. The second `AnimatedSidebarProvider` passes `keyboardShortcut={false}`.
- Terminal: one tab per session; `terminal_open` is the atomic gate (`open_or_attach`); tabs stay mounted and hide with `invisible`, never `display:none`; the pty starts only after a measurable size; unmounting drops the channel and never closes the pty; re-attaching replays the ring; a resize queues one in flight; a printed address is a link: `Ctrl`/`Cmd` + click opens it in the machine's browser (`lib/terminal-links.ts`). The palette comes from `lib/palette.ts` (document attributes plus a head `<style>`), not `resolvedTheme`.
- Git: one tab per session, commands run at the repository toplevel (`git::repository_root`), path operations are chunked, the watch refreshes only on ref-touching reports. The branch row sits at the top of the panel and asks its up-stream's remote for its refs, off-thread and at most once a minute per repository (`git::request_upstream_fetch`) — nothing else fetches.
- Files: one tab per session, preview first with the pencil as an explicit switch; drafts are LF-normalized with `eol` kept for saving; saving goes through `write_workspace_file`; a directory answers `kind: "directory"` and expands instead of reporting unreadable; `.md` renders as a document; an image opens a lightbox; no frontend disk scanning.
- Subagent tab (`state/subagent-view.ts`, `subagent-panel.tsx`): `openSubagentView` is synchronous, idempotent, and generation-guarded; streaming means its own `turnId` **or** a live parent roster; it renders `ConversationPane` with `speakers={false} fork={false} showTail={false}`; the task prompt is included only for subagent reads (`includeTaskPrompt`).
- Browser (`components/workspace/BrowserPanel.tsx`): the guest is a native child webview painted above this document, so its own visibility wish is the only way to draw over it — so only a surface that actually covers the hole hides it (`state/overlay-depth.ts` compares rectangles; a dialog covers all, a popover its own). The agent holding the page (`state/browser-agent.ts`, turn-scoped: the first `Browser` or `BrowserPreview` row until `turn_finished`) never hides it: the page stays visible and live, the toolbar goes `inert`, and a band above the hole names the hold's own `intent`, never a per-call string.

## Settings, plugins, copy

- Settings is an overlay above the still-mounted conversation (`inert`). Every section reads the real host through `state/resource.ts`: the latest answer wins, in-flight reads are shared, writes land through `adopt`, and per-workspace payloads use keyed resources. Frontend preferences live in one `state/app-settings.ts` key; theme stays owned by next-themes.
- Custom providers: the form takes a name only; the id is generated on save (`custom-draft.ts::providerIdFor`) and is not editable; every surface shows the name (`providerLabel`), never a raw provider key. Number fields use `inputMode="numeric"`, not `type="number"`. The models page draws no loading row.
- Static state chips use `AnimatedBadge animated={false}`; no `layout` projection.
- Plugin surfaces stay frozen: `views[]` and `sidebarTabs[]` become right-panel tabs, `settingsDestinations[]` becomes the plugin detail page, `panels[]` becomes a standalone window through the single command. No second registry, no second settings store.
- The marketplace is its own surface (`market/PluginMarketPage.tsx`), opened from the rail and plugin management, with a width-adapting selector and no horizontal scrolling. Its source writes are the registry's (add/refresh/remove); installing a catalogue entry is the only plugin write it owns. It seeds `anthropics/claude-plugins-official` (`plugins-store.ts::ensureBuiltinMarketplace`).
- The terminal rules travel with the built-in plugin (`rules/<name>.md`), not a skill; `skill-creator` and `plugin-creator` are seeded as native user skills. Their entries only prefill, never send.
- Every new string goes into its surface's `Localized<T>` plus `useCopy`; Chinese lives only in the application's own `*Copy.ts` files.
